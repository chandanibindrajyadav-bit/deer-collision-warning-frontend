# Copilot Prompt — Deer Detection, Tracking & Collision Warning Frontend

This replaces the earlier "wildlife monitoring" spec. The actual project is a **deer-vehicle collision
warning system**, not a general wildlife dashboard. Paste the prompt below into Copilot / Copilot Chat.
If continuing an existing session, tell Copilot to re-read this file and correct anything built against
the old spec.

---

I'm building the frontend for an AI-based **deer detection, tracking, trajectory prediction, and collision
warning system**, using **React + TypeScript**. Here is the real backend pipeline this frontend displays
data from:

1. **Detection** — a custom-trained YOLOv11 model (fine-tuned on deer via an automated Grounding DINO +
   Supervision annotation pipeline) detects deer in each video frame: bounding box, confidence score.
2. **Tracking** — ByteTrack assigns each detected deer a **persistent `trackId`** across frames, so the
   same deer keeps one ID as it moves through the scene.
3. **Trajectory** — each tracked deer has a coordinate history (a list of past positions with timestamps),
   e.g. `trajectory[3] = [(100,220), (112,225), (128,231), (141,240)]`.
4. **Motion prediction** — a Kalman Filter uses current position + velocity to predict the deer's **next
   position**, not just where it has been.
5. **Collision risk engine** — a rule-based system combines: current position, predicted future position,
   speed, heading/direction, distance to road, and estimated road boundary, to classify each track as
   **Safe** or **High Risk**, with a computed warning score.
6. **Behavior reasoning (optional, high-risk only)** — when a track is flagged High Risk, a cropped image
   of the deer is sent to a VLM (Florence-2) with the prompt "What is this deer doing?" which returns a
   short behavior label/description: e.g. Standing, Running, Grazing, Turning toward road, Crossing road.
   This is only run for high-risk events, not every frame — don't assume every detection has behavior text.
7. **Final warning / alert** — motion-based risk + (if triggered) behavior understanding are combined into
   a final warning score and surfaced as a driver/operator alert.

This is real-time (CCTV/roadside camera feeds over WebSocket) and also supports uploaded video/image
analysis for offline review. Users are road-safety/forest authority staff (admin) and researchers/analysts
(viewer, read-only).

**Tech choices to use:**
- React + TypeScript, functional components, hooks
- React Query (or SWR) for server state, Zustand for UI/session state
- React Router for routing
- Recharts or Chart.js for analytics
- Canvas overlay on top of a video element for: bounding boxes, trajectory trail (past positions), and
  predicted path (Kalman output) — rendered as distinct visual elements (e.g. solid trail vs. dashed
  predicted line), not re-rendering video frames as images
- Tailwind CSS for styling
- Role-based route guards (admin vs viewer)

**Visual design requirements:**
- Dark-themed monitoring workspace for live video; dashboard/tables can support a light mode toggle
- Status/risk colors used consistently everywhere:
  - Green = camera connected / track Safe
  - Amber = camera connecting / uncertain confidence
  - Red = camera disconnected / track High Risk
- Bounding boxes labeled with `trackId` + confidence %; trajectory shown as a trail line; predicted future
  position shown as a distinct (e.g. dashed) marker/line so it's visually separable from actual history
- High-risk alert cards must render the full VLM-generated behavior text as natural language (a sentence
  or two), not a fixed template — and must clearly show it's optional/absent for non-high-risk tracks
- Dense, sortable, filterable data tables with sticky headers
- Skeleton loaders, empty states with CTAs, and offline/reconnect banners — no blank screens or silent
  failures
- Fully responsive: desktop (sidebar + camera grid), tablet (collapsible sidebar), mobile (single-camera
  focus + bottom nav)
- Accessible: ARIA labels on icons/status dots, full keyboard navigation, visible focus states, alt text
  on thumbnails

**Data model notes for the types step:**
- `Detection`: id, `trackId`, boundingBox, confidence, timestamp, cameraId, source
- `Trajectory`: `trackId`, ordered list of `{ x, y, timestamp }` position history
- `Prediction`: `trackId`, predicted next position, predicted velocity/heading, generated by Kalman filter
- `CollisionRisk`: `trackId`, distanceToRoad, speed, headingAngle, predictedCrossingPoint (nullable),
  riskLevel (`'safe' | 'high_risk'`), warningScore
- `BehaviorAnalysis` (optional, only present when riskLevel is high_risk): `trackId`, behaviorLabel (e.g.
  'Running', 'Crossing road'), description (VLM natural-language text)
- `Camera`: existing fields plus a road boundary / geofence definition used by the collision engine
- `Alert`: combines risk + optional behavior into a final warning shown to admin/viewer, with
  acknowledgment fields
- For Upload Analysis playback syncing (step 8): a `TrackSnapshot` bundles `detection`, `trajectory`,
  `prediction`, `collisionRisk`, and optional `behavior` for one point in time — mock data for this step
  should be an **array of `TrackSnapshot`s with timestamps spanning the uploaded video's duration**, not a
  single snapshot, so the result panel can pick the closest one as playback progresses.
